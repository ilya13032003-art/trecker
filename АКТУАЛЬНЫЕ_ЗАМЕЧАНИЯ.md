# Актуальные замечания

## 1. Удаление отсутствующей подзадачи завершается NullPointerException

**Где:** `src/InMemoryTaskManager.java`, метод `removeSubTask`.

Если подзадачи нет, `searchEpic` возвращает `null`, но `removeSubTask` обращается к эпику раньше проверки. Поэтому предусмотренная обработка отсутствующего ID не работает. Это происходит и на пустом менеджере, и при передаче ID обычной задачи.

Проверь результат поиска до обращения к объекту. Отсутствие подзадачи должно обрабатываться предсказуемо: можно завершить операцию без изменений или сообщить об отказе осмысленным исключением согласно контракту метода. Существующие задачи при этом должны сохраниться. Проверь оба сценария — неизвестный ID и ID обычной задачи.

**Тесты в `test/ActualRemarksTest.java`:**

- `removeUnknownSubtaskKeepsEmptyManager` — после попытки удалить неизвестную подзадачу менеджер остаётся пустым.
- `removeSubtaskWithTaskIdKeepsTask` — передача ID обычной задачи не удаляет её и не меняет её поля; задача остаётся в списке приоритетов.

В этих тестах допустим обычный возврат либо `IllegalArgumentException` / `NoSuchElementException` и их подклассы. После допустимого отказа тесты всё равно проверяют состояние менеджера. `NullPointerException` не перехватывается: это ошибка обращения к объекту, а не предусмотренная реакция на отсутствующую подзадачу.

## 2. Эпик без подзадач получает статус IN_PROGRESS

**Где:** `src/InMemoryTaskManager.java`, метод `checkStatus` и его вызов из `removeSubTask`.

При пересчёте статуса изначально пустого эпика и после удаления последней подзадачи эпик получает `IN_PROGRESS`, хотя ожидается `NEW`. В `checkStatus` для пустой коллекции оба флага остаются `true`, поэтому выполнение попадает в последнюю ветку с `IN_PROGRESS`.

Учти пустую коллекцию при пересчёте. Проверь и изначально пустой эпик, и переход к пустому после удаления последней завершённой подзадачи — это два пути в одно состояние. Сам эпик должен остаться в менеджере.

**Тесты в `test/ActualRemarksTest.java`:**

- `emptyEpicStatusIsNew` — явный пересчёт статуса пустого эпика сохраняет `NEW`.
- `removingLastSubtaskResetsEpicToNew` — сначала подтверждает `DONE` у эпика с завершённой подзадачей, затем удаляет её и проверяет, что эпик сохранился, список подзадач пуст, а статус стал `NEW`.
